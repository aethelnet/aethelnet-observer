CRITICAL / HIGH SEVERITY ITEMS (fix ASAP)
1) Analysis cache TTL bug (database.py)
   - File/location: backend/services/database.py
   - Severity: HIGH
   - Impact: The analysis cache treated the DB timestamp as the cache insertion time. This caused
     TTL checks to immediately expire cached entries (since DB ts << now), rendering the cache
     ineffective and causing repeated DB reads and recomputations.
   - Fix implemented: cache entries now store (cached_at, ts, payload). get_latest_analysis
     checks cached_at against _cache_ttl. insert_analysis updates cache with cached_at.
   - Rationale: prevents repeated recalculation and reduces DB load.

2) Event-loop blocking sleep in async function (data_manager.py)
   - File/location: backend/services/data_manager.py -> fetch_and_store
   - Severity: HIGH
   - Impact: time.sleep() used inside an async function blocks the entire event loop,
     halting all other coroutines and causing missed market data, degraded trading responsiveness.
   - Fix implemented: replaced time.sleep(jitter) with await asyncio.sleep(jitter).

3) Unsafe attribute access for execution flag (trading_service.py)
   - File/location: backend/services/trading_service.py
   - Severity: HIGH
   - Impact: Potential AttributeError if live_manager exists but does not have is_execution_active.
     This could crash startup or prevent correct detection of execution state.
   - Fix implemented: replaced chained attribute access with getattr(getattr(...), 'is_execution_active', False).
